1

What is a framework?

Before any code, understand the idea behind the word.

A framework is a ready-made structure for building software — a skeleton you fill in, instead of building every piece yourself from raw materials. Instead of writing your own code to handle web addresses, talk to a database, or keep a user logged in, the framework already does that. You plug in the parts that make your app yours.

Think about what a website actually needs to do behind the scenes: understand the web address someone typed, fetch the right data, check whether they're logged in, protect against hackers, and send back a page. Without a framework, a beginner would have to write code for every single one of those, from scratch, before even getting to the part they actually care about. Django already has all of that built and tested — you only write the part that makes your website unique.

A way to picture it: a prefabricated house kit — walls, wiring, plumbing already standardised — instead of raw bricks, sand, and wire. Both end up as a working house. One just takes far less time and leaves far less room for mistakes.

2

Why Django, specifically

Python has several web frameworks. Here's why this course uses this one.

Django is a free, open-source framework written in Python. People call it "batteries-included" because it arrives with most of what a website needs already built in — a way to talk to a database, a login system, an admin dashboard, sensible security defaults — with nothing extra to install.

In plain terms: if you wanted to build a small college website that lets students log in and view their marks, Django already gives you the login system, the page that stores marks in a database, and even a ready-made dashboard where a teacher can add or edit that data — all before you write a single line specific to your project. You're not starting from zero; you're starting from something like 70% finished.

That makes it the shortest path from "I know basic Python" to "I built a real, working website," which is exactly today's goal.

3

Installing what you need

Two things: Python, which you already have, and Django itself.

Django isn't part of Python by default — it's an extra package you add on top, the same way you'd install any app on your phone before using it. That's what the command pip install django below actually does: pip is Python's own installer, and it downloads Django from the internet and sets it up on your computer in one step.

terminal
# check Python is installed
python --version

# install Django
pip install django

# confirm it installed correctly
python -m django --version

If all three commands print a version number with no errors, you're ready. If you see an error instead, it almost always means Python or pip isn't set up on the system PATH yet — worth asking your instructor before moving on, rather than guessing.

4

The three files to know at this level

A Django project creates several files at once. Right now, only these three matter.

You don't need to memorise what's inside each one yet — just know what job each file does, so when you open a Django project later, none of it feels random.

manage.pyRuns every command you type — start the server, create an app, and so on.
urls.pyConnects a web address to the piece of code that should handle it.
settings.pyWhere you register a new app. The only part you'll touch for now.

Put simply: when someone visits a page, urls.py decides which piece of your code should answer, and settings.py is where you told Django that your code exists in the first place. manage.py is separate from both — it's the tool you use from the terminal to actually run and manage the whole project.

About templates: you'll also work with a templates folder very soon — but Django does not create this one automatically, unlike the three above. You build it yourself, in step 5.

5

Build the project

Start to finish — from an empty folder to a styled page in your browser.

One quick idea before you start typing: in Django, a project is the whole website, and an app is one working piece inside it. Today's project is called myfirstsite, and it will contain exactly one app, called hello. Later projects might have several apps — a student portal, say, with separate apps for attendance and results — but one project with one app is the clearest way to see how the pieces fit together for the first time.

Part 1 — a page with plain text

Create the project. This generates the base folder structure for your entire site.

terminal
django-admin startproject myfirstsite
cd myfirstsite

Run the server to check the install worked.

terminal
python manage.py runserver
127.0.0.1:8000
The install worked successfully!
Congratulations on your first Django-powered page.

This is Django's own default page — you haven't written anything yet. Seeing it confirms the install is correct.

Every Django project needs an app to hold your code. We'll create one, called hello, and it's the only app we'll use for this project.

terminal
python manage.py startapp hello

Register the app by adding it to the settings file.

myfirstsite/settings.py
INSTALLED_APPS = [
    # ...existing apps...
    'hello',
]

Write the view. A view is just a normal Python function — it decides what should happen when someone visits a page, and sends something back. Here, it sends back a plain line of text.

hello/views.py
from django.http import HttpResponse

def greet(request):
    return HttpResponse("Hello, Django!")

Connect a URL to that view, directly in the project's own routing file. Right now Django has no idea when greet should run — this line tells it: "when someone visits /hello/, call this function."

myfirstsite/urls.py
from django.contrib import admin
from django.urls import path
from hello import views

urlpatterns = [
    path('admin/', admin.site.urls),
    path('hello/', views.greet, name='greet'),
]

Restart the server and visit the new address.

127.0.0.1:8000/hello/
Hello, Django!

Notice this renders in the browser's plain default serif font. HttpResponse sends raw text with no styling behind it — that's the detail Part 2 fixes.

Part 2 — the same page, properly styled

A real page comes from a template — an HTML file Django fills in and sends back. First, tell Django where to look for one, by updating settings.py.

myfirstsite/settings.py
TEMPLATES = [
    {
        'BACKEND': 'django.template.backends.django.DjangoTemplates',
        'DIRS': [BASE_DIR / 'templates'],
        'APP_DIRS': True,
        # ...OPTIONS stays unchanged...
    },
]

Only 'DIRS' changed — it was an empty list before. This tells Django: "also look inside one shared templates folder at the project root."

Now build that folder yourself, right next to manage.py — not inside hello.

folder structure
myfirstsite/
    manage.py
    templates/
        greet.html
    hello/
    myfirstsite/

Write the page — full HTML, with a little CSS built in.

templates/greet.html
<!DOCTYPE html>
<html>
<head>
  <title>My First Django Page</title>
  <style>
    body {
      margin: 0; height: 100vh;
      display: flex; align-items: center; justify-content: center;
      background: #dde9df;
      font-family: Georgia, serif;
    }
    .card {
      background: #ffffff; padding: 48px 64px;
      border-radius: 10px; border: 1px solid #dfe8dc;
      box-shadow: 0 2px 0 #dfe8dc; text-align: center;
    }
    h1 { color: #0a3620; margin-bottom: 8px; font-weight: 500; }
    p { color: #55645a; font-size: 14px; }
    .badge {
      display: inline-block; margin-top: 12px;
      padding: 5px 14px; background: #e8a33d; color: #3d2a0a;
      border-radius: 20px; font-size: 12px; font-weight: 600;
      font-family: Arial, sans-serif;
    }
  </style>
</head>
<body>
  <div class="card">
    <h1>Hello, Django!</h1>
    <p>This page was rendered from a real HTML template file.</p>
    <span class="badge">My First Django Project</span>
  </div>
</body>
</html>

Update the view to render it, instead of returning plain text.

hello/views.py
from django.shortcuts import render

def greet(request):
    return render(request, 'greet.html')

Since settings.py changed, restart the server once, then reload the page.

terminal
python manage.py runserver
127.0.0.1:8000/hello/

Hello, Django!

This page was rendered from a real HTML template file.

My First Django Project

One project, one app, one page — styled, and built entirely by hand. That's a complete, working first project.

Practice — try these on your own

Using only what's been covered so far — no new concepts needed.

Q1

Add a second view called about that returns the plain text "This is my about page" — and connect it to /about/, directly in myfirstsite/urls.py, the same way /hello/ was connected.

Q2

Create about.html inside the shared templates folder, give it its own styled card (any colors you like), and update the about view to render() it instead of returning plain text.

Q3

Edit greet.html so the card shows your own name and roll number instead of "Hello, Django!", and change the badge's background color to something different from the demo.
